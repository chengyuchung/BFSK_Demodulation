# BFSK_Demodulation 项目技术决策总览

> 本文档为项目设计阶段的"单一事实来源"，所有讨论结果汇总于此，便于后续一致引用。

## 1. 系统定位

| 项目 | 决策 |
|------|------|
| 应用场景 | **实验室原型 + 理论验证**，论文中讨论油气钻井现场扩展 |
| 核心创新 | 自适应扫频选频 + 半周期校验解调 + **磁感应耦合器穿透金属管道** |
| 通信距离目标 | 有线 10–30m（穿管双绞线），磁耦合仅需穿透金属壁（气隙 5-20mm） |
| 通信介质 | **磁感应耦合器**（穿透金属管道/屏蔽罩）+ 有线双绞线（穿管信号传输） |

## 2. 网络拓扑（四节点架构）

| 节点 | 位置 | 供电 | 通信方式 |
|------|------|------|----------|
| **井下终端** | 金属管道内 | 18650 × 2（电池） | 磁环① 与中继 BFSK 通信 |
| **中继节点** | 穿管段 / 管道出口 | 18650 × 2（电池） | 双侧磁环（井下侧① + 井上侧②） |
| **井上节点** | 井上控制柜 | 市电（18650 备用） | 磁环② + WiFi/4G 双模上行 |
| **远端上位机** | 远程 PC / 云端 | PC 电源 | MQTT over TCP/IP |

- 帧协议分层：物理层 / MAC 层 / 应用层（自定义）
- 多址方式：单井下终端轮询，TDMA 结构预留不实现
- 上位机连接：MQTT 订阅（井上节点 → 云端代理 → 远端上位机）

## 4. 射频链路参数（修正）

| 参数 | 决策 |
|------|------|
| 扫频范围 | 100kHz – 1MHz |
| 步进 | 50kHz |
| 扫频频点数 | (1000-100)/50 + 1 = **19 个** |
| 码元时长 | 1ms / bit |
| 波特率 | 1000 Baud |
| 比特编码 | f1 → 1, f0 → 0（f1 幅值最高，f0 与 f1 差 ≥ 50kHz） |
| 磁耦合气隙 | **5-20mm**（穿透金属壁，非远距离无线） |
| 磁环选型 | **锰锌铁氧体（MnZn）磁环/磁芯**，EI/EE 型，市售品 |
| 线圈 Q 值 | 30-100（普通磁环即可） |
| 功放功率 | **几十 mW – 500mW**（磁环驱动需求极低，原型阶段可用 OPA549 线性功放） |
| 有线线缆 | **穿管屏蔽双绞线**，10-30m，特性阻抗 50-100Ω |

## 5. 帧协议（5 类）

1. 握手帧（建立链路，告知 f0/f1）
2. 业务数据帧（13B：温度2B + 压力2B + 元数据）
3. 告警帧（电量、故障状态）
4. 命令帧（复位、唤醒、休眠、查询、校时）
5. 应答帧（ACK=0x00, NACK=0x01，无应答超时重传）
- CRC 校验 + 帧序号防重放
- 停等重传，最多 3 次

## 6. 时钟与同步

- 每个节点 DS3231 RTC，帧内带 Unix 时间戳
- 上位机定期下发校时命令帧
- 不做 TSN 级纳秒同步

## 7. 上位机功能（QT）

- 必做：实时波形、温压曲线、节点状态、超限告警、信道质量统计
- 加分：频谱可视化、时序预测叠加、历史回放、报表导出
- 加分：三维拓扑图、信道热力图

## 8. 时序预测算法

- **PyTorch 训练 LSTM/GRU → 导出 ONNX → QT C++ onnxruntime 推理**
- 或简化：QT 内嵌 Python 子进程推理

## 9. 验证方式

- **Matlab/Simulink**：磁感应信道模型（路径衰减 + 多径 + AWGN）+ 自适应选频算法 + 半周期校验解调算法验证
- **硬件实测**：3 节点原型，BER vs SNR、BER vs 距离、自适应选频效果

## 10. 安全策略

- CRC 校验
- 帧序号防重放
- 简单挑战码
- AES 加密列为未来工作

## 冷启动与扫频通知（对称自组织方案）

**核心思想**：
- 双方上电后都进入**"未扫频监听态"**（持续监听正弦波）
- **监听-发射错相轮换**：基于设备 ID 决定谁先发射，确保必然会合
- **信号合法性校验**：三要素校验区分"扫频信号"与"噪声"
- **双 ACK 确认机制**：必须双方都同意才能锁定 f0/f1
- **未锁定前禁止业务活动**：防止在没有可靠频率时启动业务通信

**信号合法性校验三要素**：
1. **能量**：噪声门限 +10dB 以上，且未过载
2. **频谱纯度**：Goertzel bin 内能量占比 ≥ 85%
3. **持续时长**：≥ 50ms（单频点驻留 100ms 的安全余量）

**完整扫频时序**：
```
T=0        双方上电，进入 UNSCANNED 状态
           启动 ADC 监听，启动 DMA 采样
           噪声门限标定

T=0.1s     监听-发射错相轮换开始
           A 先发射，B 先监听（或反之）

T=0.1s     A 开始扫频：19 频点 × 100ms
           B 在 ADC 路径监听

T=1.9s     A 扫频发射完，切换到比较器候选频点
           B 完成 19 频点 Goertzel 分析，选出 f0/f1

T=2.0s     B 发 SCAN_PROPOSE（含 f0/f1）
           B 状态进入 PROPOSED

T=2.5s     A 收到 SCAN_PROPOSE，验证后发 ACK
           A 发 FINAL_CONFIRM
           双方进入 LOCKED 状态

T=3.0s     应用 f0/f1，进入业务通信模式
           后续级联触发中继-井下链路扫频
```

**关键设计优势**：
- **不需要固定 f_notify**：从根本上解决"通知频率失效"问题
- **完全对称自组织**：任何一方先发都行，不依赖上电顺序
- **抗干扰能力强**：三要素校验 + 扫频模式识别 + 双 ACK 确认

详细设计见 `01_docs/02_design/扫频启动协议.md`

## 扫频选频算法（最终决策）

| 参数 | 决策 |
|------|------|
| 单频点驻留时间 | **100ms** |
| 频谱分析算法 | **Goertzel 算法**（仅测 19 个已知频点，无频谱泄露） |
| 重选频触发 | **仅被动触发**（SNR<20dB 持续 30s / BER>1% / 链路超时 5s），无定时重选 |
| 扫频发起者 | **任意一方都能发起**（对称自组织，监听-发射错相轮换） |
| 锁频确认机制 | **双 ACK 确认**（PROPOSE + ACK + FINAL_CONFIRM） |
