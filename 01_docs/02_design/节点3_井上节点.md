# 井上节点设计规格

> 本文档详细定义井上节点的硬件、软件、状态机和功耗预算。
> 井上节点是现场侧的数据汇聚点，负责接收中继节点的数据，并通过 WiFi/4G 转发到远端上位机。
> 同时具备本地显示、调试接口、本地存储能力。

## 1. 功能职责

- **磁环②侧信号接收**：通过 BFSK 接收中继转发的井下数据
- **WiFi/4G 上行**：通过无线链路将数据发送至远端上位机（云端 / PC）
- **下行命令接收**：接收远端上位机的命令，校时、查询、休眠/唤醒井下
- **本地存储**：在网络中断时缓存数据，恢复后批量上传
- **本地显示**：通过 OLED/LCD 显示节点状态、当前温压
- **配置管理**：保存网络参数、设备 ID 等

## 2. 硬件资源清单

### 主控最小系统

- STM32F407VET6（升级候选：STM32H743，更强性能）
- 8MHz 外部晶振（HSE）
- 32.768kHz 晶振（LSE，RTC）
- SWD 调试接口

### 外设分配

| 外设 | 分配 | 说明 |
|------|------|------|
| SPI1 | AD9833（井上侧） | 磁环②驱动 |
| SPI2 | OLED 显示屏 | - |
| SPI3 | SD 卡 / Flash 存储 | - |
| TIM1 | 磁环②侧输入捕获 | CH1 上升沿，CH2 下降沿 |
| TIM2 | 系统时基 | 1ms tick |
| TIM3 | PWM 蜂鸣器 | 告警音 |
| ADC1 | 磁环②侧扫频采样 | DMA |
| USART1 | 调试串口 | 115200bps |
| USART2 | ESP32 通信 | AT 指令 |
| USART3 | 4G 模块通信 | AT 指令 / MQTT |
| I2C1 | DS3231 RTC | - |
| I2C2 | OLED 显示 | - |
| USB-OTG | 本地数据导出（U 盘模式） | - |
| GPIO | 磁环使能、PA 控制、按键、LED | 多路 |

### 信号链

```
[磁环②侧]

                                                                 │
MCU ── SPI1 ──→ AD9833 ──→ OPA2333 ──→ OPA549 ──→ 磁环②原边     │
                              ↓                                    │
                         [无线上行]                                │
                              │                                    │
              ┌───────────────┴───────────────┐                    │
              ↓                                ↓                    │
        WiFi (ESP32)                    4G (Air780E)                │
        USART2                          USART3                      │
              │                                │                    │
              └────────────┬───────────────────┘                    │
                           ↓                                        │
                    [云端/远端 PC]                                    │
```

### 无线模块设计

#### 主用：ESP32 (WiFi + BLE)

- 模块型号：ESP32-WROOM-32（双核 240MHz，内置 WiFi 802.11 b/g/n + BLE 4.2）
- 接口：USART2 (115200bps) + GPIO 流控
- AT 指令集：乐鑫官方固件
- 用途：本地 WiFi 网络内的远程监控

#### 备用：4G Cat.1 模块（Air780E）

- 模块型号：合宙 Air780E（4G Cat.1，支持全网通）
- 接口：USART3 + SIM 卡座
- 协议：MQTT over TCP/IP
- 用途：无 WiFi 场景下的远程传输

#### 切换策略

```c
// net_switch.c
typedef enum {
    NET_WIFI,
    NET_4G,
    NET_OFFLINE
} NetMode;

NetMode select_network(void) {
    // 优先级：WiFi 优先（免费、稳定、低延迟）
    if (esp32_check_wifi_connected()) return NET_WIFI;
    if (air780e_check_4g_registered()) return NET_4G;
    return NET_OFFLINE;
}
```

### 显示与本地交互

- OLED 显示屏：0.96寸 SSD1306（I2C，128×64）
- 显示内容：节点状态、温压值、最近告警、网络状态
- 按键：3 个（确认 / 上 / 下），用于本地配置
- 蜂鸣器：有源蜂鸣器，告警提示

### 电源

- 主电源：市电 AC 220V → DC 12V/2A 适配器
- 备用电源：18650 × 1（断电保护，可工作 8h）
- 3.3V / 5V 供电：TPS5430
- 充电管理：TP4056

## 5. 数据上行协议（与云端 / 远端上位机）

### MQTT Topic 设计

```
topic/structure:
├── /device/{device_id}/telemetry    # 井下业务数据（温压）
├── /device/{device_id}/alarm        # 告警数据
├── /device/{device_id}/status       # 设备状态
├── /device/{device_id}/ack          # 应答
├── /server/{device_id}/cmd          # 下行命令（订阅）
└── /server/{device_id}/config       # 配置下发（订阅）
```

### JSON 数据格式（业务数据）

```json
{
  "device_id": "DOWNHOLE_001",
  "timestamp": 1726723200,
  "frame_seq": 123,
  "temperature": 25.6,
  "pressure": 1.234,
  "battery": 85,
  "signal_quality": {
    "snr_db": 32.5,
    "ber": 0.001
  }
}
```

### QoS 等级

- 业务数据：QoS 1（至少一次）
- 告警：QoS 2（恰好一次）
- 命令应答：QoS 1

## 6. 数据存储策略

### 本地缓存设计

- 存储介质：SPI Flash（W25Q64，8MB）
- 缓存结构：环形缓冲区 + 时间戳索引
- 容量：可缓存 7 天 × 1 分钟/帧 × 13B/帧 ≈ 130KB（充足）
- 网络恢复后批量上传

### 缓存数据结构

```c
// data_cache.h
typedef struct __attribute__((packed)) {
    uint32_t timestamp;      // Unix 时间
    uint16_t frame_seq;      // 帧序号
    uint8_t  data[13];       // 原始业务帧
    uint16_t crc;            // CRC 校验
} CacheEntry;
```

## 7. 与远端上位机的交互流程

```
┌────────────┐                ┌────────────┐                ┌────────────┐
│  井下节点  │ ←─── BFSK ─── │  中继节点  │ ←─── BFSK ─── │  井上节点  │
└────────────┘                └────────────┘                └────────────┘
                                                                 │
                                                                 │ WiFi/4G
                                                                 ↓
                                                          ┌────────────┐
                                                          │  MQTT代理  │
                                                          │  (云端)    │
                                                          └────────────┘
                                                                 │
                                                                 │ MQTT
                                                                 ↓
                                                          ┌────────────┐
                                                          │  远端上位机 │
                                                          │  (QT)      │
                                                          └────────────┘
```

### 完整数据流

```
1. 井下节点：采集温压 → 构造业务数据帧 → AD9833 BFSK 调制 → 磁环①
2. 中继节点：磁环①接收 → 解调 → CRC 校验 → 帧转发 → 磁环②
3. 井上节点：磁环②接收 → 解调 → CRC 校验 → JSON 封装 → MQTT 发布
4. MQTT 代理：消息路由
5. 远端上位机：MQTT 订阅 → JSON 解析 → QT 可视化
```

### 反向命令流

```
1. 远端上位机：构造命令 → MQTT 发布到 /server/{device_id}/cmd
2. MQTT 代理：消息路由到井上节点
3. 井上节点：MQTT 订阅接收 → 命令帧封装 → AD9833 BFSK → 磁环②
4. 中继节点：磁环②接收 → 解调 → 转发 → 磁环①
5. 井下节点：磁环①接收 → 解调 → 执行命令（如上报数据 / 休眠）
```

## 8. 功耗预算

| 模式 | 电流 | 说明 |
|------|------|------|
| 待机（市电） | 50 mA | MCU + OLED + RTC |
| 接收中继数据 | 100 mA | - |
| WiFi 传输峰值 | 250 mA | ESP32 突发 |
| 4G 传输峰值 | 500 mA | Air780E 发射时 |
| 离线缓存模式 | 80 mA | 接收 + 缓存 + 不上传 |

### 备用电池续航

- 18650 × 1 = 3000 mAh @ 3.7V
- 假设平均电流 100 mA
- 备用续航：**约 30 小时**

> **说明**：井上节点主要靠市电，备用电池仅在市电故障时启用。
