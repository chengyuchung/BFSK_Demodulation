# 统一帧协议 (BFSK-Link Protocol)

> 本文档定义整个 BFSK 通信链路的统一帧格式与帧类型。
> 所有节点（井下 / 中继 / 井上）共享此协议，是后续节点设计的"协议宪法"。

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| 字节对齐 | 所有字段 1/2/4 字节对齐，简化 MCU 解析 |
| 半字节编码 | TYPE / MSG_NUM 各 4 位，单字节容纳两层语义 |
| 单帧 ≤ 32B | 1ms/bit 下单帧 ≤ 32ms，加 50ms 帧间隔约 82ms，单次交互成本可控 |
| 字节填充 | HEAD=0xFF, TAIL=0x00，需对 PAYLOAD/CRC16 内特殊字节转义 |
| CRC16 | CRC-16/CCITT-FALSE，检错力强，MCU 计算 < 50μs |
| SEQ 序号 | 1 字节 0-255 循环，用于停等重传与防重放 |
| 小端序 | 所有多字节字段低字节先发（与 STM32 默认一致） |

---

## 2. 帧格式

```
偏移   字段        长度   说明
────────────────────────────────────────────────────────
  0    HEAD        1B     固定 0xFF
  1    ADDR        1B     高 4 位 = DST，低 4 位 = SRC
  2    TYPE_INFO   1B     高 4 位 = TYPE，低 4 位 = MSG_NUM
  3    SEQ         1B     帧序号 0-255 循环
  4    LEN         1B     PAYLOAD 转义后的字节数（不含 CRC/TAIL）
  5    PAYLOAD     LEN    载荷（已转义）
  ?    CRC16       2B     CRC-16/CCITT-FALSE，低字节先
  ?+1  TAIL        1B     固定 0x00
────────────────────────────────────────────────────────
最小帧：LEN=0，总长 8B（如 ACK/REPLY=READY 等）
最大帧：LEN=255，总长 263B
```

**字节序**：所有多字节字段小端（little-endian）。

---

## 3. 字节填充（转义）

由于 HEAD=0xFF 和 TAIL=0x00 是常见值，PAYLOAD 和 CRC16 字段必须做字节填充。

**转义规则**（仅对 PAYLOAD 和 CRC16 字段生效）：

```
原始字节      转义后
─────────────────────
  0xFF    →   0xFE 0x01
  0x00    →   0xFE 0x02
  0xFE    →   0xFE 0x03   （ESC 自身也要转义）
```

**接收端还原**：在 PAYLOAD/CRC16 解析过程中，遇到 `0xFE` 则读下一个字节：
- `0x01` → 还原为 `0xFF`
- `0x02` → 还原为 `0x00`
- `0x03` → 还原为 `0xFE`
- 其他值 → 帧错误（丢弃）

**不转义的字段**：HEAD、ADDR、TYPE_INFO、SEQ、LEN、TAIL。

> **设计原因**：HEAD 用 0xFF 是为了让起始字节视觉上更突出；TAIL 用 0x00 是借用"空/结束"的语义。两者都是常见值，所以 PAYLOAD 必须做转义。

---

## 4. 地址分配（DST / SRC 各 4 位）

| 地址 | 节点 |
|------|------|
| 0x0 | 保留 |
| 0x1 | 井下采集节点 |
| 0x2 | 中继节点 |
| 0x3 | 井上节点 |
| 0x4-0xE | 备用（多井下节点扩展） |
| 0xF | 广播 |

地址空间共 16 个，当前 3 个物理节点 + 1 个广播 + 12 个扩展位。

---

## 5. 帧类型编码（TYPE，4 位）

| TYPE | 名称 | 说明 |
|------|------|------|
| 0x0 | QUERY | 查询帧 - 主动请求数据 |
| 0x1 | CONTROL | 控制帧 - 设置参数/状态 |
| 0x2 | ASK | 询问帧 - 传输前握手 |
| 0x3 | REPLY | 回复帧 - 应答 ASK 或业务帧 |
| 0x4 | ALARM | 警报帧 - 主动告警 |
| 0x5-0xC | 保留 | 未来扩展 |
| 0xD | SCAN | 扫频/锁频专用 |
| 0xE-0xF | 保留 | - |

---

## 6. 子类型编码（MSG_NUM，4 位）

按 TYPE 大类独立计数。

### 6.1 QUERY（查询帧）

| MSG_NUM | 名称 | 载荷 | 说明 |
|---------|------|------|------|
| 0x0 | 温压数据 | (空) | 触发对方上报温压 |
| 0x1 | 电池信息 | (空) | 触发对方上报电池电压/电量 |
| 0x2 | 故障状态 | (空) | 触发对方上报传感器故障 |
| 0x3-0xF | 保留 | - | 扩展 |

**响应方式**：被查询方收到 QUERY 后，通过 REPLY(ACK) 确认，然后发送业务数据帧。
- 业务数据帧也属于 QUERY 大类，带具体数据载荷
- 或者：响应方用 REPLY(ACK) + 后续数据帧

### 6.2 CONTROL（控制帧）

| MSG_NUM | 名称 | 载荷 | 说明 |
|---------|------|------|------|
| 0x0 | 设定休眠时间 | [sleep_sec(2)] | 设置本机下次休眠时长 |
| 0x1 | 休眠 | (空) | 立刻进入休眠 |
| 0x2 | 唤醒 | (空) | 强制唤醒（适用中继/井上） |
| 0x3 | 设置温度阈值 | [temp_low(2)] [temp_high(2)] | 单位 0.01°C，整数（如 5000=50.00°C）|
| 0x4 | 设置压力阈值 | [press_low(2)] [press_high(2)] | 单位 0.01MPa，整数 |
| 0x5-0xF | 保留 | - | 扩展 |

> **休眠时间 vs 休眠命令**：
> - 0x0 是"配置"，告诉对方"你以后按这个时长休眠"，对方持久化保存
> - 0x1 是"动作"，告诉对方"现在立刻进入休眠"
> - 0x2 是"唤醒"，强制把对方从休眠中拉出（适用中继被井上唤醒）

### 6.3 ASK（询问帧）

| MSG_NUM | 名称 | 载荷 | 说明 |
|---------|------|------|------|
| 0x0 | 请求空闲确认 | (空) | "你能接收数据吗？" |
| 0x1-0xF | 保留 | - | 扩展 |

**流程**：发送方发 ASK → 接收方回 REPLY(READY/BUSY) → 决定是否继续。

### 6.4 REPLY（回复帧）

| MSG_NUM | 名称 | 应答对象 | 载荷 |
|---------|------|---------|------|
| 0x0 | READY（有空） | ASK | (空) |
| 0x1 | BUSY（忙） | ASK | (空) |
| 0x2 | ACK（接收成功） | 业务帧 | (空) |
| 0x3 | NACK（接收失败） | 业务帧 | [err_code(1)] |
| 0x4 | RETRY_REQ（重传请求） | 业务帧 | (空) |
| 0x5-0xF | 保留 | - | 扩展 |

**NACK 错误码**：
| err_code | 含义 |
|----------|------|
| 0x01 | CRC 校验失败 |
| 0x02 | 长度异常 |
| 0x03 | TYPE/MSG_NUM 未知 |
| 0x04 | 目标地址不匹配 |
| 0x05 | SEQ 序号重复/过期 |
| 0x06 | 业务忙（正在处理其他事务） |
| 0x07 | 参数越界 |

### 6.5 ALARM（警报帧）

| MSG_NUM | 名称 | 载荷 | 说明 |
|---------|------|------|------|
| 0x0 | 电量低 | [batt_pct(1)] | 当前电量百分比 |
| 0x1 | 温度超限 | [current_temp(2)] [limit_type(1)] | 当前温度 + 超限类型 |
| 0x2 | 压力超限 | [current_press(2)] [limit_type(1)] | 当前压力 + 超限类型 |
| 0x3 | 传感器故障 | [fault_code(1)] [fault_data(2)] | 故障码 + 故障数据 |
| 0x4 | 链路失败 | [retry_count(1)] | 重传次数耗尽 |
| 0x5-0xF | 保留 | - | 扩展 |

**limit_type**：
- 0x01 = 低于下限
- 0x02 = 高于上限

**fault_code**：
| fault_code | 含义 |
|------------|------|
| 0x01 | PT100 断路 |
| 0x02 | PT100 短路 |
| 0x03 | 压力传感器无响应 |
| 0x04 | ADC 异常 |
| 0x05 | RTC 异常 |

### 6.6 SCAN（扫频帧）

| MSG_NUM | 名称 | 载荷 |
|---------|------|------|
| 0x0 | SCAN_PROPOSE | [f0_khz(2)] [f1_khz(2)] |
| 0x1 | PROPOSE_ACK | [f0_khz(2)] [f1_khz(2)] |
| 0x2 | FINAL_CONFIRM | [f0_khz(2)] [f1_khz(2)] |
| 0x3 | RESCAN_REQ | (空) |

> 详细流程见 `01_docs/02_design/扫频启动协议.md`。
> 扫频帧在 LOCKED 前使用，不走 SEQ 重传（扫频本身会重试整个流程）。

## 7. CRC 校验

**算法**：CRC-16/CCITT-FALSE
- 多项式：`0x1021`
- 初始值：`0xFFFF`
- 输入不取反
- 输出不取反
- 输出宽度：16 位

**覆盖范围**：从 ADDR（第 1 字节）到 PAYLOAD 末尾。
- **不包含**：HEAD、CRC16 自身、TAIL
- 不包含 SEQ 和 LEN——这两个字段在 CRC 之前

**字节序**：低字节先发（CRC16_L, CRC16_H）。

## 8. 帧序号 SEQ 与重传

### 8.1 SEQ 规则

- 1 字节，0-255 自动循环
- 发送方每发一帧 SEQ +1（255 后回 0）
- ACK 中的 SEQ 字段**回显被应答帧的 SEQ**
- 重传时 SEQ 不变（同一帧重发）

### 8.2 停等重传

```
发送方                          接收方
   │                              │
   │ ── DATA(SEQ=5) ────────→    │
   │                              │
   │ 启动 200ms 定时器            │ 解析 + 处理
   │                              │
   │ ←──── ACK(SEQ=5) ─────────  │ （或 NACK/RETRY）
   │                              │
   │ 定时器清除，发下一帧          │
   │                              │
   │ （超时未收到 ACK）            │
   │                              │
   │ ── DATA(SEQ=5) 重传 ───→    │ 最多 3 次
   │                              │
   │ 第 3 次失败                   │
   │                              │
   │ 发 ALARM(链路失败)            │
```

### 8.3 防重放

- 接收方维护最近 32 个已收 SEQ 的滑动窗口
- 收到的 SEQ 在窗口内 → 判定为重放，丢弃
- 收到的 SEQ 不在窗口内 → 接受，更新窗口

### 8.4 例外：扫频帧

扫频阶段（UNSCANNED/SCANNING/PROPOSED）的帧不要求严格重传：
- 整个扫频流程本身会重试（19 频点 × N 轮）
- 扫频失败由扫频状态机处理，不走 SEQ 重传机制
- 进入 LOCKED 后，所有业务帧严格执行停等重传

## 9. 通信流程示例

### 9.1 数据查询（标准 ASK + REPLY 流程）

```
上位机          井上          中继          井下
  │              │             │             │
  │              │             │             │ 上电，LOCKED
  │              │             │             │
  │ 触发查询温压  │             │             │
  │              │ ASK(READY_REQ)             │
  │              │ ────────→   │             │
  │              │             │ 中继透传     │
  │              │             │ ────────→   │
  │              │             │             │
  │              │             │ ← REPLY(READY)
  │              │ ←────────   │             │
  │              │             │             │
  │              │ QUERY(温压)  │             │
  │              │ ────────→   │             │
  │              │             │ ────────→   │
  │              │             │             │
  │              │             │ ← QUERY(温压) + 数据载荷
  │              │ ←────────   │             │
  │              │             │             │
  │              │ REPLY(ACK)  │             │
  │              │ ────────→   │             │
  │              │             │ ────────→   │
  │              │             │             │
  │              │ 上报上位机   │             │
```

> 注：上面简化为单向 ASK 握手。也可以让井下定时主动上报（无需 ASK）。

### 9.2 控制命令（设置休眠时间）

```
上位机          井上          中继          井下
  │              │             │             │
  │ 设置休眠 30秒 │             │             │
  │              │ CONTROL(0x0, sleep_sec=30)
  │              │ ────────→   │             │
  │              │             │ ────────→   │
  │              │             │             │
  │              │             │ 持久化保存   │
  │              │             │ ← REPLY(ACK)
  │              │ ←────────   │             │
  │              │             │             │
```

### 9.3 主动告警

```
上位机          井上          中继          井下
  │              │             │             │
  │              │             │             │ 温度异常
  │              │             │             │
  │              │             │ ← ALARM(温度超限)
```

## 10. 解析状态机（接收端）

```
                          ┌─────────┐
                          │  IDLE   │ 等待接收
                          └────┬────┘
                               ↓ 收到 0xFF
                          ┌─────────┐
                          │ HEAD    │ 收 ADDR/TYPE_INFO/SEQ/LEN
                          └────┬────┘
                               ↓ 字段齐全
                          ┌─────────┐
                          │ PAYLOAD │ 按 LEN 收字节（转义还原）
                          └────┬────┘
                               ↓
                          ┌─────────┐
                          │  CRC    │ 收 2B CRC，校验
                          └────┬────┘
                               ↓
                          ┌─────────┐
                          │  TAIL   │ 收 0x00
                          └────┬────┘
                               ↓
                          ┌─────────┐
                          │ CHECK   │ CRC 通过 + TAIL=0x00？
                          └────┬────┘
                           是 ↓    ↓ 否（丢弃）
                          ┌─────────┐
                          │  DONE   │ 帧交给上层
                          └─────────┘
```

**异常处理**：
- 任何阶段收到错误字节 → 回到 IDLE，丢弃已收数据
- 超时（帧间间隔 > 200ms 未完成） → 回到 IDLE
- CRC 错误 → 丢弃，回 REPLY(NACK, err_code=0x01)

## 11. 实现注意事项

1. **字节填充性能**：转义/还原是逐字节操作，应在接收 ISR 中完成，避免占用主循环时间。

2. **CRC 计算位置**：在字节填充还原后做 CRC（用原始字节算），不要用转义后的字节算。

3. **SEQ 窗口大小**：32 是经验值。如果节点数 > 4 或高吞吐场景可调到 64。

4. **LEN 字段含义**：是 PAYLOAD **已转义后**的字节数。MCU 接收时按 LEN 收完 PAYLOAD 后，再读 2B CRC + 1B TAIL。

5. **广播帧**：DST=0xF 的帧不需要 ACK，接收方也不重传。

6. **未 LOCKED 状态**：业务帧禁止发送（除扫频帧），避免在不可靠频率上通信。

7. **跨节点中继**：中继节点透传时需记录 DST/SRC，修改本节点地址后再转发，不能简单广播。
