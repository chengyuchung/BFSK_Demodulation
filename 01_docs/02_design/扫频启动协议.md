# 扫频启动协议 — 对称自组织设计

> 本文档是冷启动与扫频通知的唯一工程实施依据。
> 设计思想：未扫频态 + 正弦波监听 + 信号合法性校验，从根本上解决冷启动问题。

## 1. 设计核心思路

### 1.1 核心问题

```
冷启动死循环：
  想扫频 → 需要双方在某个频率上通信协调
  想通信 → 需要先约定好一个频率
```

### 1.2 解决思路：对称自组织

```
双方上电 → 都进入"未扫频监听态"
       → 谁先发信号都行，另一方自动识别并加入
       → 不需要固定 f_notify，不需要主从关系，不需要时间同步
```

### 1.3 信号合法性校验（关键）

**核心问题**：监听方如何区分"约定的扫频信号"和"噪声"？

```c
// 三要素合法性校验（必须同时满足）
bool is_valid_scan_signal(GoertzelResult* r) {
    return (r->magnitude_db > (NOISE_FLOOR_DB + 10))  // 要素1：能量足够
        && (r->magnitude_db < (MAX_VALID_DB - 30))    //          未过载
        && (r->spectral_purity > 0.85)                // 要素2：频谱纯净
        && (r->duration_ms >= 50);                    // 要素3：驻留时长够
        // 频率范围（100k-1MHz）在 ADC 配置中已限定
}
```

| 检测要素 | 噪声特征 | 约定扫频信号特征 |
|---------|---------|-----------------|
| **能量** | 与噪声底相当 | 高出噪声底 10-50 dB |
| **频谱纯度** | 频谱扩散，多频点 | Goertzel bin 内 85%+ 能量 |
| **持续时长** | < 5ms 短脉冲 | ≥ 50ms（单频点驻留 100ms） |
| **频率稳定性** | 频率漂移大 | 单频点驻留期间稳定 |
| **出现模式** | 随机 | 按 100ms 间隔切换频点 |

## 2. 状态机总览

### 2.1 四态状态机（接收方视角）

```
                        上电/复位
                            ↓
                  ┌──────────────────┐
                  │ UNSCANNED        │  未扫频监听态
                  │ (持续监听正弦波)  │  默认状态
                  └────────┬─────────┘
                           ↓ 检测到合法扫频信号
                  ┌──────────────────┐
                  │ SCANNING         │  扫频测量态
                  │ (做 Goertzel)    │
                  └────────┬─────────┘
                           ↓ 选频完成，发 RESULT
                  ┌──────────────────┐
                  │ RESULT_SENT      │  等待对方确认
                  │ (等待 ACK)       │
                  └────────┬─────────┘
                           ↓ 收到 ACK
                  ┌──────────────────┐
                  │ LOCKED           │  已锁定
                  │ (业务通信+休眠)   │  允许所有功能
                  └──────────────────┘
```

### 2.2 状态切换表

| 当前状态 | 触发事件 | 下一状态 | 允许的活动 |
|---------|---------|---------|-----------|
| UNSCANNED | 检测到合法扫频信号 | SCANNING | 监听、Goertzel 测量 |
| UNSCANNED | 本机决定开始主动扫频 | SCANNING_TX | 发射 19 频点 |
| SCANNING | 完成 19 频点测量 | RESULT_SENT | 发送 SCAN_PROPOSE |
| SCANNING_TX | 完成 19 频点发射 | RESULT_TX | 监听 ACK/接收 SCAN_PROPOSE |
| RESULT_SENT | 收到对方 ACK | LOCKED | 业务通信、休眠唤醒等 |
| RESULT_TX | 收到对方 PROPOSE（含 f0/f1）| LOCKED | 应用 f0/f1 |

## 3. 接收侧：未扫频监听详细流程

### 3.1 监听算法

```c
typedef struct {
    int16_t freq_khz;        // 检测到的频点
    uint32_t start_tick;     // 信号起始时间戳
    uint32_t end_tick;       // 信号结束时间戳
    float peak_db;           // 峰值能量
    float purity;            // 频谱纯度
} SignalCandidate;

SignalCandidate g_candidate_history[32];
uint8_t g_candidate_count = 0;

void unscanned_rx_loop(void) {
    // 1. ADC 持续采样（DMA 模式）
    HAL_ADC_Start_DMA(&hadc1, adc_buffer, ADC_BUFFER_SIZE);

    uint32_t last_full_scan_tick = 0;

    while (g_state == UNSCANNED) {
        // 每 100ms 检查一次
        if (HAL_GetTick() - last_full_scan_tick >= 100) {
            last_full_scan_tick = HAL_GetTick();

            // 2. 对 19 个频点做 Goertzel
            for (int i = 0; i < 19; i++) {
                uint16_t f_khz = g_freq_list[i];
                GoertzelResult r = goertzel_single_bin(
                    adc_buffer, ADC_BUFFER_SIZE, sample_rate_hz, f_khz * 1000);

                // 3. 三要素合法性校验
                if (is_valid_scan_signal(&r)) {
                    // 4. 累积到候选历史
                    append_candidate(f_khz, &r);

                    // 5. 检查是否构成"扫频模式"
                    if (is_scan_pattern_detected()) {
                        enter_scan_state();
                        break;
                    }
                }
            }
        }
    }
}
```

### 3.2 扫频模式识别

**问题**：单频点检测到不足以判断是"扫频"，可能是干扰。

**解决**：检测"周期性频点切换"模式

```c
typedef struct {
    uint16_t freq_history[8];   // 最近 8 个频点
    uint32_t time_history[8];   // 对应时间
    uint8_t count;
} ScanPatternDetector;

bool is_scan_pattern_detected(void) {
    ScanPatternDetector* pd = &g_pattern_detector;

    // 需要至少 5 个连续不同频点
    if (pd->count < 5) return false;

    // 检查 1：频点严格不同
    for (int i = 0; i < pd->count - 1; i++) {
        if (pd->freq_history[i] == pd->freq_history[i+1]) {
            return false;  // 连续相同，不是扫频切换
        }
    }

    // 检查 2：切换间隔 ≈ 100ms（容差 80-150ms）
    for (int i = 0; i < pd->count - 1; i++) {
        uint32_t dt = pd->time_history[i+1] - pd->time_history[i];
        if (dt < 80 || dt > 150) {
            return false;
        }
    }

    // 检查 3：频点符合已知列表（100k-1MHz 步进 50k）
    for (int i = 0; i < pd->count; i++) {
        if (pd->freq_history[i] < 100 || pd->freq_history[i] > 1000) {
            return false;
        }
        if ((pd->freq_history[i] - 100) % 50 != 0) {
            return false;
        }
    }

    return true;  // 全部条件满足，确认是扫频信号
}
```

### 3.3 三要素校验实现

```c
bool is_valid_scan_signal(GoertzelResult* r) {
    // 要素 1：能量在合理区间
    if (r->magnitude_db < (NOISE_FLOOR_DB + 10)) return false;  // 太弱
    if (r->magnitude_db > MAX_VALID_DB) return false;            // 过载或异常强

    // 要素 2：频谱纯度（Goertzel bin 内能量占比）
    // 通过计算相邻 bin 的能量比来评估
    float total_energy = compute_total_band_energy(adc_buffer, r->freq_hz, 5e3);  // ±5kHz 范围
    float peak_energy = r->magnitude_linear * r->magnitude_linear;
    float purity = peak_energy / total_energy;
    if (purity < 0.85) return false;

    // 要素 3：持续时长 ≥ 50ms
    if (r->duration_ms < 50) return false;

    return true;
}
```

**噪声门限的标定**：

```c
void calibrate_noise_floor(void) {
    float sum_db = 0;
    int valid_count = 0;

    for (int i = 0; i < 19; i++) {
        GoertzelResult r = goertzel_single_bin(
            adc_buffer, ADC_BUFFER_SIZE, sample_rate_hz, freq_list[i] * 1000);

        if (r.magnitude_db < -60) {  // 滤除异常强
            sum_db += r.magnitude_db;
            valid_count++;
        }
    }

    g_noise_floor_db = (sum_db / valid_count) + 10;  // 加 10 dB 余量
}
```

## 4. 发送侧：主动扫频触发时机

### 4.1 监听态/发射态轮换

**问题**：对方也处于监听态，那谁先发？

**解决**：双方都实施"监听-发射轮换"，错开时机：

```c
typedef enum {
    PHASE_LISTEN,       // 监听态（接收）
    PHASE_TRANSMIT      // 发射态（发送扫频）
} ListenTransmitPhase;

typedef struct {
    ListenTransmitPhase phase;
    uint16_t listen_ms;     // 监听时长
    uint16_t transmit_ms;   // 发射时长
    uint32_t phase_start_tick;
} PhaseScheduler;

void unscanned_loop(void) {
    PhaseScheduler* ps = &g_phase_scheduler;

    // 初始化（基于设备 ID）
    if (ps->phase == PHASE_LISTEN && ps->phase_start_tick == 0) {
        // 根据设备 ID 决定初始相位，确保错开
        if (g_device_id == NODE_TERMINAL) {
            // 井下节点先发射
            ps->phase = PHASE_TRANSMIT;
            ps->listen_ms = 1000;
            ps->transmit_ms = 1900;  // 19 频点 × 100ms
        } else {
            // 中继节点先监听
            ps->phase = PHASE_LISTEN;
            ps->listen_ms = 1000;
            ps->transmit_ms = 1900;
        }
    }

    switch (ps->phase) {
        case PHASE_LISTEN:
            if (detect_scan_signal()) {
                enter_scan_state();
            }
            // 监听 1s 后切换
            if (elapsed(ps->phase_start_tick) >= ps->listen_ms) {
                ps->phase = PHASE_TRANSMIT;
                ps->phase_start_tick = HAL_GetTick();
            }
            break;

        case PHASE_TRANSMIT:
            transmit_sweep_19freqs();  // 19 频点逐个发射
            // 完成后切换
            if (elapsed(ps->phase_start_tick) >= ps->transmit_ms) {
                ps->phase = PHASE_LISTEN;
                ps->phase_start_tick = HAL_GetTick();
                save_f_notify_if_acked();
            }
            break;
    }
}
```

### 4.2 错相设计原理

```
时间轴：
  节点A（井下，先发射）:  TX ─────────┐ L  ┌─TX ─────────┐ L ...
                                └─19频点─┘ 1s └─19频点─┘
  节点B（中继，先监听）:  L  ┌─TX ─────────┐ L ┌─TX ─...
                          1s └─19频点─┘ 1s

相位 1: A 发射, B 监听
  → A 不知道 B 在监听的，但 A 发出去，B 能收到

相位 2: A 监听, B 发射
  → B 不知道 A 在监听，但 B 发出去，A 能收到

相位 3+: 重复
```

**关键观察**：总有一个相位是"一个发射，另一个监听"，双方都能识别对方的扫频信号。

### 4.3 19 频点扫频发射实现

```c
void transmit_sweep_19freqs(void) {
    // 切换到正弦波路径
    ad9833_set_single_tone_mode();
    switch_rx_path(PATH_ADC);  // 自己也切，方便检测 ack（如果对方恰好回复）

    for (int i = 0; i < 19; i++) {
        uint16_t f_khz = freq_list[i];
        uint32_t f_hz = f_khz * 1000;

        // 设置 AD9833 频率
        ad9833_set_freq(f_hz);

        // 同步监听一次（如果对方恰好此时发自己也会收到，但概率极低）
        delay_ms(100);

        // 检查是否收到"stop"信号
        if (received_stop_signal()) {
            break;
        }
    }

    // 切回监听态
    ad9833_set_freq_pair(f0_candidate, f1_candidate);  // 临时切换到候选频点
    switch_rx_path(PATH_COMPARATOR);  // 接收对方 ACK
}
```

## 5. 双侧会合后的 ACK 确认机制

### 5.1 为什么需要 ACK

**问题**：
- A 完成扫频，选出 f0/f1
- A 把结果发给 B
- B 也可能在自己扫频，得出了另一个 f0/f1
- 双方必须**确认对方**用同一对频率

**解决**：扫频确认协议

```
帧类型：
  0xD0 = SCAN_PROPOSE   我扫频完成了，建议用 f0/f1
  0xD1 = PROPOSE_ACK    我同意，验证一下
  0xD2 = FINAL_CONFIRM  确认锁频
```

### 5.2 完整状态机实现

```c
typedef enum {
    UNSCANNED,        // 监听态
    SCANNING_RX,      // 检测到对方扫频 → 同步接收
    SCANNING_TX,      // 主动扫频发射
    PROPOSED,         // 已发出 SCAN_PROPOSE，等 ACK
    ACKED,            // 收到 ACK，发 FINAL_CONFIRM
    LOCKED            // 锁频成功
} ScanState;

void scan_state_machine(void) {
    ScanState s = g_scan_state;

    switch (s) {
        case UNSCANNED:
            // 监听态/发射态轮换
            unscanned_loop();
            break;

        case SCANNING_RX:
            // 已同步上对方扫频，进入 SCANNED
            // 等对方发 PROPOSE，再进入 PROPOSED 状态
            break;

        case SCANNING_TX:
            // 自己扫频完，发出 PROPOSE
            transmit_propose(&my_freq_pair);
            g_scan_state = PROPOSED;
            break;

        case PROPOSED:
            // 等 ACK，1 秒超时则重发
            if (received_propose_ack()) {
                transmit_final_confirm();
                g_scan_state = ACKED;
            } else if (timeout_1s()) {
                transmit_propose(&my_freq_pair);  // 重发
            }
            // 也许会收到对方的 PROPOSE（对方也选完频了）
            if (received_propose(&other_pair)) {
                // 比较 my_pair vs other_pair
                if (is_better(&my_pair, &other_pair)) {
                    // 我更优，再用我的重发
                    transmit_propose(&my_pair);
                } else {
                    // 对方更优，接受对方的
                    apply_freq_pair(&other_pair);
                    transmit_propose_ack(&other_pair);
                    g_scan_state = PROPOSED;  // 等对方最终确认
                }
            }
            break;

        case ACKED:
            // 等 FINAL_CONFIRM 确认
            if (received_final_confirm()) {
                g_scan_state = LOCKED;
                log("Scan locked!");
                save_freq_pair_to_eeprom(&g_freq_pair);
            }
            break;

        case LOCKED:
            // 完全锁定，进入业务通信模式
            enter_data_mode();
            break;
    }
}
```

### 5.3 频点优劣协商

当双方都扫频完毕，可能选出不同的 f0/f1：

```c
bool is_better(const FreqPair* a, const FreqPair* b) {
    // 比较规则
    int a_score = a->score;  // 总能量
    int b_score = b->score;

    // 1. 优先选总能量高的
    if (a_score > b_score * 1.1) return true;  // a 显著优

    // 2. 总能量相当，选频率更对称的（更接近 500kHz）
    int a_balance = abs(a->f0_khz - 500) + abs(a->f1_khz - 500);
    int b_balance = abs(b->f0_khz - 500) + abs(b->f1_khz - 500);
    return a_balance < b_balance;
}
```

```c
    init_phase_scheduler();
```

## 7. 关键保护机制

### 7.1 扫频前的严格隔离

**重要约束**：未进入 LOCKED 状态前，**不允许以下活动**：

```c
bool is_operation_allowed_in_state(Operation op) {
    ScanState s = g_scan_state;

    if (s == LOCKED) {
        return true;  // LOCKED 状态允许所有活动
    }

    // 未锁定状态只允许扫频相关活动
    switch (op) {
        case OP_SLEEP:           return false;  // ✗ 禁止休眠
        case OP_BUSINESS_TX:     return false;  // ✗ 禁止业务发射
        case OP_WAKEUP_BEACON:   return false;  // ✗ 禁止唤醒信标
        case OP_FREQ_SWEEP:      return true;   // ✓ 允许扫频
        case OP_SCAN_RESPONSE:   return true;   // ✓ 允许应答
        default:                 return false;
    }
}
```

**好处**：
- 防止"在没有可靠频率的情况下启动业务通信"
- 防止"在没有 f0/f1 的情况下进入休眠"
- 保证整个系统启动流程的完整性

### 7.2 三层防误判

```c
// 防误判三重保险

// 第一层：单频点信号合法性校验（已经实现）
if (!is_valid_scan_signal(&r)) continue;

// 第二层：扫频模式识别（频点周期性切换）
if (!is_scan_pattern_detected()) continue;

// 第三层：必须收到对方 ACK 才锁定（不允许单方面决定）
if (!received_peer_ack()) continue;

// 三层都通过才能进入 LOCKED 状态
enter_locked_state();
```

### 7.3 噪声门限自适应

环境噪声是变化的（昼夜、温湿度、附近设备启停），噪声门限需要自适应：

```c
void adaptive_noise_floor_update(void) {
    // 每 60 秒重新标定一次
    static uint32_t last_calib_tick = 0;

    if (HAL_GetTick() - last_calib_tick >= 60000) {
        last_calib_tick = HAL_GetTick();

        // 在已知空闲时段（业务通信结束时）做标定
        if (g_is_idle_window) {
            calibrate_noise_floor();
            log("Noise floor recalibrated: %.1f dB", g_noise_floor_db);
        }
    }
}
```

## 8. 业务流程整合

### 8.1 完整启动流程

```
上电/复位
  ↓
硬件初始化
  ↓
噪声门限标定
  ↓
进入 UNSCANNED 状态（持续监听正弦波）

  ↓
PROPOSE → 等对方 ACK
  ↓
FINAL_CONFIRM 确认
  ↓
进入 LOCKED 状态
  ↓
启用所有功能：
  - 业务通信
  - 休眠唤醒
  - 主动扫频（被动触发）
  - 时钟同步
```

## 9. 失败恢复与告警

### 9.1 扫频失败的诊断

```c
typedef enum {
    SCAN_FAIL_NONE,
    SCAN_FAIL_NO_SIGNAL,        // 始终未检测到信号
    SCAN_FAIL_WEAK_SIGNAL,      // 信号太弱
    SCAN_FAIL_INTERFERENCE,     // 19 个频点都被干扰
    SCAN_FAIL_PEER_NO_ACK,      // 对方一直不应答
    SCAN_FAIL_TIMEOUT,          // 总超时
} ScanFailReason;

ScanFailReason g_last_scan_fail_reason = SCAN_FAIL_NONE;

void log_scan_failure(ScanFailReason reason) {
    g_last_scan_fail_reason = reason;
    log("Scan failed: %s", scan_fail_reason_str(reason));
    alarm_manager_trigger(ALARM_SCAN_FAILED);
}
```

## 10. 实现优先级

| 优先级 | 功能 | 说明 |
|--------|------|------|
| **P0** | UNSCANNED 监听 + 信号合法性校验 | 协议核心 |
| **P0** | 19 频点 Goertzel 测量 | 已有，复用 |
| **P0** | SCAN_PROPOSE/ACK 协议 | 必须保证双向确认 |
| **P1** | 监听-发射错相轮换 | 优化会合速度 |
| **P1** | 扫频模式识别算法 | 防止误判 |
| **P1** | 频点优劣协商 | 双方都扫频时 |
| **P2** | 自适应噪声门限 | 长期稳定性 |
| **P2** | LED/串口诊断 | 调试辅助 |
| **P3** | 上位机调试命令 | 实验室用 |

## 11. 设计优势总结

```
1. 不需要固定 f_notify
   → 没有"如果 f_notify 失效"的兜底问题

2. 完全对称自组织
   → 任何一方先发都行，不依赖上电顺序

3. 信号合法性校验
   → 噪声不会误触发扫频流程

4. 双 ACK 确认
   → 必须双方都同意才能锁定，避免不一致

5. 严格的进入条件
   → 未锁定前禁止业务通信，保证通信质量

6. 算法可证明
   → 错相轮换必然会合，合法性校验必然过滤噪声
```

**核心思想**：**用物理信号特征代替协议约定**，让对方发什么我们都能识别。
