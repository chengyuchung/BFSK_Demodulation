# 扫频启动协议设计

## 背景

发送方只往油管上发正弦波，接收方在未建链阶段无法解调复杂报文，必须仅凭物理信号特征完成四件事：

1. 判断对方是否正在扫频（启动识别）
2. 判断扫频何时结束（结束判定）
3. 知道当前测到的是哪个频点（频点归属）
4. 将选定的最优频对告知发送方（结果回传）

---

## 一、扫频启动识别——三重物理特征校验

接收方处于 IDLE（等待态）时，ADC 持续以 10 kHz 采样，算法每隔 10 ms 提取最新的 40 ms 数据进行评估。**只有同时满足以下三重约束，才判定为合法扫频信号，触发扫频流程**。

### 门槛一：幅值有效性门限（滤除背景底噪）

计算当前 40 ms 窗口内的峰峰值 Amax，必须显著高于当前工况的静态底噪 NoiseFloor：

- **约束条件**：Amax ≥ 2 × NoiseFloor

微弱热噪声与漏电杂波直接丢弃。

### 门槛二：波峰一致性校验（滤除瞬态干扰）

在 40 ms 窗口内寻找全局最大波峰 P0 及其相邻波峰 P-1、P+1，校验相邻波峰幅值的一致性：

- **约束条件**：(Pk 幅值 - P0 幅值) / P0 幅值 ≤ 15%

真实扫频正弦波包络高度平稳；电焊、电机启停等产生的电火花表现为单个尖峰或剧烈衰减波，无法通过此校验。

### 门槛三：标称频点就近对齐（滤除工频谐波）

根据波峰间隔采样点数 ΔN 折算瞬时频率：

- **换算公式**：f_calc = fs / ΔN = 10000 / ΔN  (Hz)

将 f_calc 与预设 19 个候选频点（125 Hz～1025 Hz，步进 50 Hz）进行比对：

- **容差窗口**：±15 Hz
- 若落在合法频点容差内（如测得 172 Hz 归入 175 Hz），判定为命中有效频点
- 若落在空白带（如 150 Hz，介于 125 和 175 正中间）或工频带（50 Hz、100 Hz），判定为环境噪声

> **状态转移**：一旦捕获到第一个合法频点，状态机立刻由 `IDLE` 切换为 `SWEEPING`，并清空历史幅值表。

---

## 二、扫频结束判定——双重保障机制

**严禁采用"数够 19 个频点"作为结束条件**。铁质油管在恶劣井况下某些频点可能被严重衰减至底噪以下，数频点必然导致程序永久卡死。系统采用以下双重保障：

### 机制 A：850 ms 会话硬超时看门狗（防死锁兜底）

发射端发射 19 个频点，每个 40 ms，总耗时固定为 19 × 40 ms = 760 ms。

接收端在**命中第一个有效频点的瞬间**，立即启动一个 **850 ms 的单向会话倒计时定时器**（预留 90 ms 滑动延迟与晶振容差）。定时器归零时，无论丢失了多少频点，单片机无条件强行判定扫频结束，跳转进入最优频对决选逻辑。

### 机制 B：尾部连续静默检测（快速提前收敛）

发射端发完最后一个 1025 Hz 频点后，切断功率输出转为静默态。若接收端在 `SWEEPING` 状态下，**连续 80 ms～100 ms（8～10 个滑动步长）均未检测到高于底噪的有效正弦信号**，且表内已记录至少两个频点，即可提前判定扫频结束，立即收敛。

## 三、频点归属确定——测量方与发射方分离的解决

"幅值最大"只能在接收侧测出（信号经链路衰减后才知好坏），但切换频率的动作由发射方完成。双方无时钟同步、无控制通道，接收方如何知道当前测到的是哪个频点？

核心思路：**以高频次重叠滑动消除时隙错位，以预设频表就近对齐解决频点归属，以全频点独立建档完成信道摸底**。

### 1. 高重叠滑动分析窗口（消除时序错位）

接收方不追踪发射方切频的微秒级跳变点，而是采用"40 ms 分析窗口 + 10 ms 滑动步长"（重叠率 75%）机制：

```
发射方时序（每频点 40ms）:
[──── 125Hz ────][──── 175Hz ────][──── 225Hz ────] ...

接收方滑动步长（每 10ms 刷新一次）:
|── 窗1 ──|       → 跨界混叠（丢弃）
   |── 窗2 ──|    → 稳稳截取 175Hz 核心稳态正弦（提取幅值与频率，写入 Table[175Hz]）
      |── 窗3 ──| → 截取 175Hz 尾段（再次计算，仅保留更大值）
```

每个发射频点被接收端分析窗口连续覆盖 **3 到 4 次**，无论收发时钟存在多少毫秒偏移，至少有一个 40 ms 窗口能完整包裹当前频点的纯净正弦波，消除频点被切碎或遗漏的盲区。

### 2. 局部波峰测距 + 标称频表就近映射（频率准确定位）

接收方不依赖发射方告知当前频点，依靠信号自身物理周期和预置频表完成闭环对齐：

1. **提取纯净正弦周期**：在 40 ms 稳态数据中，测出主波峰与相邻波峰的采样点间隔 ΔN
2. **瞬时物理频率换算**：f_calc = 10000 / ΔN  (Hz)
3. **Nearest Snap 就近映射**：在预置频点表 F = [125, 175, 225, 275, ..., 1025] Hz（19 项）中寻找绝对差值最小的标称项，容差 ±15 Hz

示例：
- 测得 f_calc = 171.8 Hz，差值 |171.8 - 175| = 3.2 Hz → 认定为 **175 Hz**
- 测得 f_calc = 223.5 Hz → 认定为 **225 Hz**

通过映射，连续模拟量被量化为离散频点编号（索引 0～18）。

### 3. 独立成绩单机制（避免在线淘汰导致死锁）

接收方在单片机内存中开辟 19 元素幅值记录数组（仅占 38 字节）：

```c
int16_t Max_Amplitude_Table[19] = {0}; // 对应 125Hz ~ 1025Hz 历史最大幅值
```

- **只记录，不淘汰**：每 10 ms 解算出合法频率和幅值后，仅与该频点自身历史记录比较：

```c
if (current_amplitude > Max_Amplitude_Table[target_index]) {
    Max_Amplitude_Table[target_index] = current_amplitude;
}
```

即使后续频点幅值更低，也不丢弃前面的记录，所有频点各自独立打分、互不影响。

- **全局最优频对决选**：850 ms 定时器超时后，对 `Max_Amplitude_Table` 进行全局决策：
  1. 频差下限约束：|f1 - f0| ≥ 150 Hz ~ 200 Hz，避免 50 Hz 邻近频点码间串扰
  2. 避开 2 倍谐波频点，规避油管磁饱和非线性失真
  3. 在满足物理约束前提下，挑出幅值最大的两个频点作为最终 BFSK 通信频对 (f0, f1)

## 四、扫频结果回传——接收方向发送方的频对通知

扫频结束后，接收方已经通过 `Max_Amplitude_Table` 决策出了最优的两个频点 f0 和 f1。然而此时通信双方面临一个根本性的困境：**扫频阶段本身就是"没有建链"的阶段**——双方仅靠物理正弦波的幅值和频率来传递信息，没有任何应用层协议、没有确认应答机制、没有专用控制通道。

接收方如何将 f0 和 f1 告知发射方？这是一个典型的"反向通信"问题，与扫频阶段的问题恰好镜像对称：扫频阶段是发射方主导、接收方被动感知；结果回传阶段是接收方主导、发射方需要感知，但双方手里都没有现成的通信协议。

具体来说，存在以下子问题：

- **物理通道瓶颈**：接收方此刻只有"往油管上注入信号"这一种物理手段，无法像以太网那样随意构造任意报文。接收方只能通过某种可被发射方"感知"的信号特征来传达信息。
- **发射方感知能力有限**：发射方在扫频结束后处于什么状态？它是继续发正弦波、切换为纯接收态，还是完全静默？不同的假设会导致完全不同的通知策略。
- **编码容量约束**：如果用简单的"有无信号"或"单频点"来编码，最多只能传达几个比特的信息。如何用有限的信号样式可靠地传递 19 个频点中选出的两个编号（每个编号需要 log2(19) ≈ 5 bit，两个编号共需约 10 bit）？
- **时序不确定性**：接收方发出通知信号的时机与发射方的预期之间可能存在较大偏差。如果发射方在等待期间误将背景噪声当作通知信号，或反之，会导致建链彻底失败。

### 4.1 核心痛点与物理矛盾

在刚测完信道衰减时，收发双方尚未建立数字通信链路，不能假设存在任何可靠的默认控制频点来传输数据包——这是冷启动无数字信道的根本矛盾。

铁质油管在物理上是一根连续的无差别导电总线（尤其在地面车间联调或浅井工况下），井上发射扫频波时，中继 1、中继 2、井下底节会同时感应到信号。扫频结束后的回传和确认信号极易引发多节点总线抢发碰撞（Collision）或跨级误触发（False Triggering）——这是单总线广播与跨级串扰的矛盾。

### 4.2 机制一：最优频点的物理自载波传递与闭环握手

接收方无需运行复杂的未建链数据编码，而是利用信道物理互易性，采用"自载波交替回传 + 发射方多路监听 + 短帧 ACK 状态翻转"的极简闭环逻辑。

#### 4.2.1 物理层自载波交替回显（101010... 特征序列）

接收方不需要发包告知频点编号，而是直接把选中的两个物理频点 f0、f1 作为载波，以标准交替方波（即数字特征码 0xAA，二进制 101010...）反向注入油管，持续发射 300～450 ms。

- **物理穿透力极强**：由于这两个频点刚被实测证明为整段链路衰减最小的频点，上行反传时 SNR 全频段最高，具有极强的抗衰减穿透力。
- **兼具总线占位作用**：这串高能量的交替信号不仅通知了发射方，还充当了总线忙信号，让下游正在监听的节点立刻感知到。

#### 4.2.2 发射方的能量提取

发射方发完扫频后，立即关闭功放并进入接收模式，后台运行 19 路并行的窄带 Goertzel 算法（每路带宽仅数 Hz）。发射方在监听窗口内，会清晰看到 19 个频点中只有对应的那两个频点能量柱在高速交替跳变，其他 17 个频点全处于低噪底状态。发射方由此无需盲解调，直接精准锁定目标频对 f0、f1。

#### 4.2.3 严格的 ACK 状态机翻转（绝不盲目切换）

发射方锁定频点后，立即用 (f0, f1) 向下发送一个极短的 BFSK 确认帧（ACK）。接收方只有成功解调出该 ACK 帧，才会正式从"被测待机从机"切换为建链工作态。如果未收到 ACK，说明可能受到突发噪声干扰，接收方绝不擅自翻转状态，等待上级发起重新扫频。

#### 4.2.4 握手时序图

```
[发射方：井上主机]                                    [接收方：中继 1]
        │                                                        │
        │ ─────── 1. 19 频点扫频 (125~1025Hz, 760ms) ─────────> │
        │                                                        │ 850ms 定时到期，决选 f0/f1
        │ （发射关闭，转为 19 路监听态）                          │
        │                                                        │
        │ <────── 2. 独占时隙发射 f0/f1 交替方波 ────────────── │
        │         (101010...，持续 300~450ms)                    │
        │                                                        │
  19 路能量检测锁定 f0/f1，                                     │
  配置本地 BFSK 调制器                                          │
        │                                                        │
        │ ─────── 3. 以 (f0, f1) 下发 ACK 确认帧 (150ms) ────> │
        │                                                        │ 校验 ACK 成功！
        │                                                        │ 状态翻转为【工作态】
        │                                                        │ 准备向下级接力扫频
```

### 4.3 机制二：共享总线上的全节点防串扰与防误判机制

为确保同一根总线上的多个节点（中继 1、中继 2、中继 3、井下底节）互不干扰、永不踩踏，系统确立三大安全防线：

#### 防线一：静态硬件 ID 绑定时间窗口（Fixed Time-Slot TDMA）

每个节点在出厂固化代码时，硬性分配专属的发言时隙，绝不在运行时动态变更顺位，彻底消除分布式脑裂和重试时的时序撞车：

- **扫频基准期（0～850 ms）**：所有节点接收扫频波，各自计算并填充 19 格成绩单。
- **消震静默期（850～950 ms）**：全总线静默 100 ms，消除铁管机械/电磁余震，前级运放归零。
- **窗口 1（950～1550 ms，共 600 ms）**：中继 1 独占时隙（仅 ID = 1 允许开火回显）。
- **窗口 2（1550～2150 ms，共 600 ms）**：中继 2 独占时隙（仅 ID = 2 允许开火回显）。
- **窗口 3（2150～2750 ms，共 600 ms）**：中继 3 独占时隙（仅 ID = 3 允许开火回显）。
- **窗口 4（2750～3350 ms，共 600 ms）**：井下底节独占时隙（仅 ID = 4 允许开火回显）。

#### 防线二：向上总线侦听主动退避（Bus Snooping & Yielding）

下游节点不需要去解析复杂的报文，只需执行最纯粹的物理能量侦听：

- **侦听铁律**：下游节点（如中继 2）在自己的窗口（窗口 2）到达之前，必须全程侦听管柱总线。
- **主动退让**：只要中继 2 在窗口 1 检测到管柱上有强信号跳变（即中继 1 正在发射 101010... 或井上在回 ACK），立刻判定："窗口 1 有人说话，证明上级呼叫的是更高顺位的中继 1，本次扫频与我无关。"中继 2 立刻清空刚刚暂存的扫频数据，主动放弃竞争，退回静默待机态。

#### 防线三：频点多样性安全防线（有效频点 ≥ 5 的真扫频判决）

彻底解决"上级节点的回复信号或 ACK 误触发下游扫频状态机"的隐患：

- **物理特征差异**：真正的扫频信号在时间轴上依次遍历 125 Hz～1025 Hz 的多个频点；节点间通信/握手信号（101010... 或 ACK）在物理频域上永远只有 f0 和 f1 这 2 个频点。
- **硬性门限判据**：所有节点在 850 ms 会话定时器超时时，必须核对 19 格成绩单中被有效点亮的独立频点总数：
  - 有效非零频点数 ≥ 5 → 确认总线上经历了一场真正的全频段扫频，允许进入时隙退避流程
  - 有效非零频点数 < 5 → 判定这只是上级节点之间的正常数据通信或环境脉冲干扰，直接静默丢弃，绝不触发扫频结算

### 4.4 全流程运行全景演进（以三中继级联为例）

整套系统通过"自上而下、击鼓传花"的接力模式完成整网扫频：

```
阶段一：地面井上 ──扫频──> 中继 1 建链（总耗时约 1.75s）
-----------------------------------------------------------------------------------------
1. 井上发射 125~1025Hz (760ms)。全节点收音填表，均统计到 ≥ 5 个频点。
2. 窗口 1 开启：中继 1 准时在窗口 1 发射 f0/f1 (101010...)。
3. 中继 2、3 侦听到窗口 1 有信号，判定非本级业务，主动清空数据，退回休眠。
4. 井上捕获中继 1 回传，下发 ACK 帧。中继 1 校验通过，锁定链路 1，翻转为发射机。

阶段二：中继 1 ──向下扫频──> 中继 2 建链（总耗时约 2.35s）
-----------------------------------------------------------------------------------------
1. 中继 1 启动功放向下扫频 (760ms)。中继 2、3、井下收音填表（井上已建链旁路）。
2. 窗口 1 到达：中继 1 是发射机不说话，中继 2/3 无权说话 → 【窗口 1 自然静默】。
3. 窗口 2 开启：中继 2 发现前面窗口 1 全程死寂，判定"轮到我了"，在窗口 2 发射回显！
4. 中继 3 侦听到窗口 2 有动作，主动清空数据退让。
5. 中继 1 下发 ACK 帧。中继 2 校验通过，锁定链路 2，翻转为发射机。

阶段三：中继 2 ──向下扫频──> 中继 3 建链（窗口 1、2 自然静默，中继 3 在窗口 3 回显）

阶段四：中继 3 ──向下扫频──> 井下底节建链（窗口 1、2、3 自然静默，井下在窗口 4 回显）
=========================================================================================
最终：全线贯通！井下底节沿建好的数字链路逐级上报 READY 帧，系统进入正式业务数据采集。
```

## 五、断链角色仲裁与数据断点续传（基于 4 标志位的事务状态机）

### 核心难点

多级中继拓扑中，一旦某两级节点之间通信中断：

- 如果双方都去主动扫频，总线必定崩溃
- 如果双方都死等，系统必定死锁
- 如果在断链时丢弃了正在传输的井下数据，系统将失去业务价值

### 核心方案

引入 **4 标志位** 事务上下文 + 数据暂存区（Store-and-Forward），通过本地状态自发决定节点角色（谁扫频、谁监听），坚守"仅由上级主动向下扫频，下级只准静默监听"的铁律。

### 5.1 事务状态机定义（4 大标志位）

每个节点在 RAM 中维护一个 64 字节的 `pending_buffer` 以及 4 个描述当前事务状态的标志位：

1. **① 从上接收成功**：已收到上级命令
2. **② 向下转发成功**：已将命令发给下级，并收到下级的下行 ACK
3. **③ 从下接收成功**：已收到下级采集回传的数据
4. **④ 向上转发成功**：已将数据发给上级，并收到上级的上行 ACK

### 5.2 断链场景的状态自发推演与断点续传

当节点发生通信超时时，单片机根据这 4 个标志位，就能绝对精准地判断出物理故障点，并自动执行对应的挽救措施。

#### 场景 A：下行传命令断链（如中继 2 发给中继 3 失败）

- **中继 2 的状态**：标志位①为真，标志位②为假（向下发了，但没收到中继 3 的 ACK）
- **中继 2 的动作**：判定下行物理阻断！将该命令锁入 `pending_buffer`，并作为主控方主动向下打出 760 ms 扫频波
- **中继 3 的状态**：4 个标志位全为默认值（根本没收到命令），超时后准时切入【被扫频监听态】
- **断点续传**：扫频握手成功后，中继 2 立即从缓存区调出命令，重新下发

#### 场景 B：上行传数据断链（如中继 3 发给中继 2 失败）

- **中继 3 的状态**：标志位①②③为真（已采到数据），但标志位④为假（数据往上发了，但没收到中继 2 的 ACK）
- **中继 3 的动作（关键防线）**：判定上行阻断！绝对禁止中继 3 向上发起扫频！将宝贵的传感器数据死锁在 `pending_buffer` 中，就地切入【被扫频监听态】
- **中继 2 的状态**：标志位②为真，但标志位③为假（等下级数据超时）
- **中继 2 的动作**：判定下级回传受阻！作为上级主动向下打出 760 ms 扫频波去打捞中继 3
- **断点续传**：链路复活锁定后，中继 3 立即从缓存区调出刚刚憋在肚子里的数据，重新推给中继 2，实现恶劣信道下的数据零丢失

## 六、全生命周期休眠逻辑与 Flash 快速自愈

### 核心难点

节点在长时间未收到信号时，无法分辨是"信道断了"还是"业务真的空闲"：

- 如果误判断链而去频繁扫频，会耗尽电池
- 如果误判空闲而去盲目休眠，会导致带着数据死锁

### 核心方案

将 **4 标志位是否干净** 作为隐式休眠的唯一物理入口，配合 Flash 参数缓存实现极速重连。

### 6.1 唯一合法的隐式休眠入口（清洁态鉴别）

节点如果经历长时间的总线静默（例如 3.0 秒没有任何信号），单片机只需检查本地的 4 标志位：

- **情况 A（事务挂起态）**：只要有任意一个标志位不是默认值（说明身上背着还没走完的流程），物理定性 100% 为通信断链故障！绝对不允许休眠！节点必须带数据进入扫频监听或主动扫频
- **情况 B（清洁态 Clean）**：4 个标志位全部为默认值（未接任何任务，或上一轮数据的闭环已经彻底走完）。这是系统唯一允许隐式休眠的入口

### 6.2 清洁态下的"两段式"降级休眠（防幽灵死锁）

即使满足了清洁态，节点也无法分辨"是上级压根没发命令，还是上级的命令在第一跳就断了"。因此执行严密的降级动作：

**第一段（黄金抢救期）**：绝不马上闭眼！节点先切入常开的【被扫频监听态】，安静地听管柱 3～5 秒。如果此时上级发起了扫频，立刻配合建链。

**第二段（零发射静默巡检）**：如果 3～5 秒内全无扫频信号到来，方可彻底证实"总线上真的没有任务"。铁律：坚决不向上发送"我要休眠了"的 ACK 报备！（防止撞毁总线上其他节点的隐蔽操作）。节点悄无声息地关闭 10 kHz 连续采样，切入超低功耗的【间歇式巡检】（睡 900 ms，醒 100 ms 快听能量）。一旦未来有 760 ms 的扫频波打来，这 100 ms 的窗口足以瞬间将其唤醒。

### 6.3 极低代价的 Flash 快速自愈（Probe-First Fallback）

为避免每次异常都触发极其耗时的全网冷扫频（约 7.0 秒），系统引入断链快速抢救机制：节点在 Flash 中持久化存储历史建链成功的 (f0, f1) 频点。

- **第 1 级（优先盲探，耗时 < 300 ms）**：上级节点在需要重连时，优先用 Flash 里的历史频点发极短的 PING 包。如果下级信道未发生物理质变，下级秒回 PONG，链路瞬间原频复活，免除扫频
- **第 2 级（降级冷扫频，耗时约 1.75 s）**：只有当 PING 超时 3 次（证明地层环境改变导致原频点彻底失效），上级才擦除 Flash，降级启动 125～1025 Hz 的 760 ms 物理扫频，重新打榜选频
